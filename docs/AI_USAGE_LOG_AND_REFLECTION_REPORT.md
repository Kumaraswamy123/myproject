## AI-Generated vs Manually Directed Work

The AI-assisted parts included the initial React frontend, Node.js backend routes, JSON-based persistence layer, API tests, OpenAPI file, and supporting documentation. AI also helped debug specific issues such as the hidden logout label, form feedback, repeated issue editing, layout overlap, and rate limiting.

The manually directed parts included the problem statement, feature priorities, checking the running app in the browser, identifying UI problems, requesting changes, reviewing API behavior, setting up GitHub access, and deciding which fixes were needed. My own manual understanding was important because AI output still had to be checked against the assignment requirements and actual app behavior.

## Manual vs AI Workflow

Compared with a fully manual workflow, AI reduced the time needed to create boilerplate, connect frontend and backend code, write documentation, and prepare automated tests. It made development faster because I could ask for focused improvements instead of rewriting the whole application each time.

However, manual review was still necessary. Some issues only became clear after running the app, such as weak submit feedback, the overlapping My Issues section, and the logout label visibility. AI helped produce solutions quickly, but I still needed to test the result, understand the code, and confirm that the final behavior matched the assignment.

## Benefits and Limitations

The main benefits were faster development, better organization of files, easier debugging support, and help with documentation. AI was especially useful for repetitive work such as API test cases, OpenAPI schemas, and explaining how frontend and backend parts connect.

The main limitations were that AI output needed careful verification, generated reflection text could not be submitted directly as personal learning, and some UI problems were only visible after real browser testing.
